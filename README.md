# まち｜MACHI LIFE

現在地や指定座標の街を読み込み、自分のキャラクターで歩き、建物に入り、日常を過ごす3Dブラウザゲームです。買い物・仕事・食事・休息、自宅の家具配置を体験できます。

- ブラウザ版: https://uni-tadayasu.github.io/world/
- オンライン版: https://machi-life.hisa-0128-1996.chatgpt.site/
- 遊び方・データ・プライバシー: `dist/about.html`

## 開始方法

「現在地から始める」でブラウザの位置情報を許可するか、緯度・経度を指定します。位置情報を使わず、生活体験用の架空の「ひかり町」を選ぶこともできます。

実地図モードは半径約450mの範囲から開始します。OpenStreetMapの建物輪郭・道路中心線と、公開DEMの標高を使います。外壁・窓・室内、未登録の高さや道路幅はゲーム用の簡易表現です。現地の写真や私室を復元する機能ではなく、実世界の通行を案内するナビゲーションでもありません。

位置が建物や水域の中に重なる場合、歩ける屋外を開始点にし、移動した距離を表示します。地図には取得した元の位置も残します。測位に失敗した場合に、架空の街を現在地として表示しません。

## キャラクター

- 標準キャラクターと服の色を選べます。
- 正面、背面、左右の写真から、輪郭を使った簡易3Dキャラクターを作成します。これはAIによる精密復元やフォトグラメトリではありません。精細度を上げても、写真にない形は復元されません。
- テクスチャ内蔵のGLB / VRMを読み込めます。上限は50MB・200万ポリゴン。付属アニメーション、または対応する人型骨格から動作を付けます。
- Draco・Meshopt・KTX2圧縮、外部ファイルを参照するモデルは対象外です。
- 写真・モデルは端末内で処理し、復元用にIndexedDBへ保存します。この処理からサーバーへアップロードしません。

## 自宅とセーブ

自宅の家具を間取り図で配置・移動・回転し、壁・床・家具の色を変更できます。配置は3D室内に反映します。家具の重なりや玄関の通り道には制限があります。

ゲストの部屋はブラウザ内、オンライン版でログインした部屋はそのアカウントに保存します。暮らし・設定はブラウザに保存します。セーブJSONの書き出し・読み込みに対応しますが、写真や3DモデルはJSONに含まれません。別の端末やURLへ移す場合は元のファイルを再度読み込んでください。

## 所有物と生活感

街のゲーム内フリーマーケットでは、植物・チェア・照明・テーブル・本棚を購入して、自分の所有物にできます。名前・色の変更、修理、手入れ、収納に対応します。所有物メニューから、自分の部屋へ家具を移せます。実在する物の所有権を扱う機能ではなく、プレイヤー別のゲーム用の物品です。

自宅では照明の切り替え、掃除、植物の水やりができます。所有物はゲストなら端末内、オンライン版でログイン中なら自分のアカウントに保存します。通信に失敗した場合は画面に表示し、再同期できます。

## オンライン版とGitHub Pages版

GitHub Pagesにはブラウザ用静的ファイルだけを配信します。アカウント・投稿・チャット・部屋などのオンラインAPIは、専用オンライン版のSites Workerで提供します。静的版からオンライン機能を開くと、その版へ案内します。ChatGPT認証はオンライン版で処理します。

音声通話は明示的な参加操作後にマイクを要求し、WebRTCを利用します。ネットワーク条件やTURN中継の設定によって接続できない場合があります。TURNなどの認証情報を静的ファイルやリポジトリへ書き込まないでください。

## ローカルで実行

`dist/`内の静的版はビルド不要です。Three.jsと必要なローダーは`dist/vendor/`に同梱しています。main/root公開用のルートHTMLとSEOアセットは、変更後に`node scripts/build.mjs`で同期してください。

```bash
python3 -m http.server 8000 --directory dist
```

ブラウザで `http://localhost:8000/` を開きます。ファイルを直接ダブルクリックする`file://`実行は、ES Modulesやブラウザのセキュリティ制限により対象外です。公開時はHTTPSを使用してください。JavaScriptとWebGL 2、対応するGPUが必要です。

構文確認:

```bash
for file in dist/*.js; do node --check "$file"; done
```

確認する主な操作は、初回起動、現在地取得の許可・拒否、座標入力、街の移動、入退室、生活行動、家具編集、写真・モデルの復元、タッチ操作、ゲームパッドです。オンラインの認証・保存・通話はオンライン版で確認します。

## mainから自動公開

既存の「Deploy from a branch → main / (root)」と「GitHub Actions」の両方に対応しています。`node scripts/build.mjs` は、`dist/`のゲームからルートの`index.html`・`about.html`・SEOアセットを同期します。ルートHTMLはJavaScript・CSSを`dist/`から読み込み、ホームのURLを `/world/` に保ちます。`_config.yml`はREADMEによるトップページ化を防ぎ、Worker・開発スクリプト・依存関係・設定ファイルをJekyll配信から除外します。

main更新のワークフローは、GitHub Pages APIを読み取って現在の`build_type`を確認します。`legacy`（main/root配信）の場合は検証だけで終了し、GitHub標準のブランチ公開に任せます。`workflow`の場合だけ静的アーティファクトを配置します。Pages設定を変更するAPIは呼びません。この分岐で二つの配信による上書き競合を避けます。

ワークフローは`contents: read`、`pages: write`、`id-token: write`だけを要求します。ビルド時のnpmインストールは不要です。canonical・サイトマップ・OGPのURLは `https://uni-tadayasu.github.io/world/` を使用します。ドメイン変更時は`index.html`のhead、`about.html`、`robots.txt`、`sitemap.xml`を合わせて更新してください。

オンライン版は `node scripts/build.mjs` で同じ静的ファイルを含むWorkerを生成し、Sitesの公開処理でD1マイグレーションとともに配置します。Pagesのワークフローはオンライン版のサーバーをデプロイしません。サーバー変更時はオンライン版も更新してください。Node.js 24以降の開発プレビューは `npm run dev`。ローカルSQLiteを使用し、ログイン済みのユーザーを偽装しません。

## 外部データと制限

- 地図: © OpenStreetMap contributors / [ODbL](https://www.openstreetmap.org/copyright)。取得先は[Private.coffeeのOverpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)。ユーザーが選んだ位置の周辺データを要求し、1要求35秒、429時の自動再試行は行いません。キャッシュは最大4件・24時間です。
- 地形: [Mapzen Terrain Tiles](https://registry.opendata.aws/terrain-tiles/)のTerrarium形式。地域ごとの元データは[帰属情報](https://github.com/tilezen/joerd/blob/master/docs/attribution.md)を参照してください。DEMは近似標高です。
- 地図の取得先へは緯度経度、標高配信元へは周辺タイル番号が送られます。現在地を他プレイヤーへ自動共有しません。
- 位置情報や地図データが利用できない地域、未記録の建物、古いデータがあります。未取得の地域全体を事前収録しているわけではありません。
- 大きなモデル、高解像度、端末の発熱・メモリー不足は描画速度に影響します。品質設定を調整してください。
- ブラウザのサイトデータ削除、保存容量不足、プライベートモードでは端末内データが残らない場合があります。
- アプリマニフェストとホーム画面アイコンを提供しています。全世界の地図をオフラインで利用する機能はありません。
