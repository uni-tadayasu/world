# 暗号資産への交換：実装範囲と接続前の決定事項

更新日: 2026-11-25

## 現在の公開機能

メニューの「報酬と交換」は、準備状況とこのブラウザの報酬台帳を確認する画面です。**本番では実際の交換・暗号資産の送金を行いません。** 送金先サービスは未接続で、交換レート・手数料・最低交換額も未確定です。

Bitcoinを最初の接続対象として表示します。Ethereumやその他の暗号資産を利用できるという表示はしません。ウォレットアドレス・秘密鍵・シードフレーズ・本人確認書類を収集するフォームはありません。

## 生活通貨と交換対象の報酬

既存の `life.state.money` は端末内で保存し、初期所持金、仕事・買い物、セーブの読み込みなどで変更します。サーバーで収益や原資を裏付けた通貨ではありません。これを送信・コピーして交換残高に変えるAPIは作りません。

交換対象の報酬は、サーバーに記録する整数ポイントです。初期値は0です。画面には以下を区別して表示します。

| 値 | 管理と意味 |
|---|---|
| ゲーム内所持金 | 端末の生活通貨。換金対象外 |
| 交換対象の報酬 | サーバーで確認された報酬のうち、申請に使用していない分 |
| 申請中の報酬 | 申請のために確保した分。同時に別の申請へ使用できない |
| 申請履歴 | 当該ブラウザのプレイヤーが作った申請のみ |

対象となる報酬の付与条件はまだ決めていません。サーバー側の台帳サービスには確認済み報酬イベントの受け入れ境界を用意しますが、ブラウザから自由にポイントを加算する公開エンドポイントは設けません。同一イベントの再送を二重に加算しないこと、残高を超える同時申請を受けないこと、取消時の返却が一度だけであることを回帰テストの対象にします。

## HTTPの公開範囲

`worker/social.js` の既存のブラウザ接続、同一オリジン確認、プレイヤーID照合を通したうえで処理します。新しいログイン画面は追加しません。

| API | 現在の動作 |
|---|---|
| `GET /api/social/exchange` | 当該プレイヤーの残高・履歴と `available:false`、`mode:"preparing"` を返す |
| `GET /api/social/exchange/requests` | 当該プレイヤーの申請履歴のみを返す |
| `POST /api/social/exchange/quote` | `503 exchange_unavailable`。本番の見積サービスは未接続 |
| `POST /api/social/exchange/requests` | `503 exchange_unavailable`。ポイントの予約や実送金を行わない |
| `POST /api/social/exchange/requests/:id/cancel` | `503 exchange_unavailable`。本番の変更操作はすべて停止中 |

本番HTTP処理からは未接続のproviderを使用します。環境変数に文字列の有効化フラグを置いただけで実送金を開始できる構成にはしません。内部のサービス境界へテスト用providerを渡して、見積の期限、残高の予約、取り消し等を検証します。これは本番で送金できることを意味しません。

## 実送金までに必要な実装と決定

### 運営主体と提供地域

運営国、対象とする国・地域、年齢条件、サービスとして行う行為を確定します。日本で暗号資産の売買・交換等を業として提供する場合の登録制度は、金融庁の案内を参照してください。2026年6月からは所属業者の委託によるサービス仲介業の制度もあります。今回の報酬サービスがどの制度に該当するかは、ポイントの設計・契約・資金の流れを含め個別に確認する必要があります。

- [金融庁：暗号資産・電子決済手段関係](https://www.fsa.go.jp/policy/virtual_currency02/)
- [金融庁：FinTechサポートデスク・暗号資産関係Q&A](https://www.fsa.go.jp/news/27/sonota/20151214-2.html)
- [金融庁：電子決済手段・暗号資産サービス仲介業](https://www.fsa.go.jp/common/shinsei/denanchuukai/index.html)

この文書は登録や適法性を確認・保証するものではありません。

### 原資と報酬条件

支払い原資の保有者、資金の入金・確保、報酬の付与条件と上限を決めます。払い出せる額は確保された原資と一致させる必要があります。単に長時間プレイしたというクライアント申告だけで、無制限に換金可能なポイントを発行しません。

### 送金事業者との接続

利用する事業者の契約と対応地域を確認したうえで、サーバー側providerを実装します。確定済み報酬イベントの真正性、送金先の検証、見積の期限・手数料・最低額、事業者への冪等な送金依頼、通知の署名検証、送金結果の照合・再試行を扱います。

本実装には、暗号資産の購入、ホットウォレット、秘密鍵の管理、ブロックチェーンへの送信、入出金の監視、実送金dispatcherは含まれません。事業者を選んだうえで、API・通知の仕様に合わせて追加する必要があります。

### 利用者の確認と回復

現在のゲームはブラウザのCookieでプレイヤーを区別します。別のブラウザ、Cookie削除、有効期限切れ、別ドメインへの移動では元の台帳へアクセスできなくなる場合があります。この仕組みだけで実金銭の長期管理を開始せず、本人確認や送金先の所有確認、端末を失った場合の回復方法を事業者とともに設計します。ChatGPTへのログインを復活させることとは別の要件です。

## 検証範囲

台帳はローカルSQLiteで12件、画面は決定的なHTTP応答で4件の専用テストを通過しています。ゲーム全体の回帰は172件合格・失敗0件です。実在するユーザーの残高を増減させず、暗号資産や金銭を送金していません。公開版では準備中の状態と読み取りAPIを確認します。接続後は、事業者の検証環境で実際の通知・見積失効・二重要求・資金不足・送金の不明状態を確認してから利用者向けに有効化する必要があります。
